# Telegram-бот для PegaProx

Бот управляет Proxmox через PegaProx. Каждый пользователь Telegram подключает свой
аккаунт PegaProx, и бот работает с его правами: ни больше, ни меньше, чем в веб-интерфейсе.
Все действия пишутся в журнал аудита PegaProx от имени пользователя.

## Что умеет

- Кластеры: состояние, сколько нод в сети и гостей запущено.
- Ноды: CPU, RAM, диск, аптайм; перезагрузка и выключение (PegaProx разрешает это только
  для ноды в режиме обслуживания).
- VM и контейнеры: список по страницам, поиск `/find`, запуск, выключение, перезагрузка,
  жёсткая остановка, reset, пауза. Опасные действия спрашивают подтверждение.
- Снапшоты: список, создание (своё имя или автоматическое), откат, удаление.
- Бэкапы: список, запуск бэкапа в выбранное хранилище (vzdump, snapshot, zstd).
- Миграция на другую ноду (для запущенной VM вживую).
- Firewall: датацентр (вкл/выкл, правила вкл/выкл) и правила отдельной VM/CT.
- Хранилища и последние задачи кластера.
- Оповещения: список активных, подтверждение, и бот сам присылает новые (`/notify off`
  выключает).
- Пользователи (`/users` или кнопка «👥 Пользователи»):
  - **PegaProx**: список, создание, смена роли, включение и выключение, новый пароль,
    сброс 2FA, удаление. Нужно право `admin.users`; ограничения PegaProx (тенанты, роль не
    выше своей, нельзя удалить себя или последнего админа) действуют как в веб-интерфейсе.
  - **Proxmox VE** (у каждого кластера): пользователи (создание, пароль для realm pve,
    включение и выключение, группы, удаление), группы и их участники, роли (свои можно
    создавать, менять и удалять), права (ACL): выдать роль пользователю или группе на весь
    кластер, на одну VM/CT или на любой путь, и забрать. Это могут только администраторы
    PegaProx с токеном роли admin. `root@pam` бот не даёт выключить или удалить.
  - Пароли принимаются только в личном чате, и бот сразу удаляет сообщение с паролем.
- `/api METHOD /api/путь [JSON]`: любой запрос к API PegaProx, если кнопок не хватает.
  Например `/api GET /api/clusters/<id>/ha/status`.

## Установка

Нужен Debian/Ubuntu с доступом к PegaProx и к `api.telegram.org`. Обычно это тот же LXC,
где стоит PegaProx.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. На хосте из папки репозитория:
   ```bash
   sudo bash tgbot/deploy/install.sh
   ```
   Скрипт ставит бота в `/opt/proxmox-tg-bot` со своим venv, создаёт пользователя
   `proxmox-tg-bot`, файл настроек `/etc/proxmox-tg-bot.env` и службу `proxmox-tg-bot`.
3. Впишите токен в `/etc/proxmox-tg-bot.env` (`TG_BOT_TOKEN=...`) и запустите:
   ```bash
   sudo systemctl restart proxmox-tg-bot
   journalctl -u proxmox-tg-bot -f
   ```

### Настройки (`/etc/proxmox-tg-bot.env`)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TG_BOT_TOKEN` | | токен от @BotFather, обязателен |
| `PEGAPROX_URL` | `https://127.0.0.1:5000` | адрес PegaProx |
| `PEGAPROX_VERIFY_TLS` | `false` | `false` для самоподписанного сертификата, `true` или путь к CA |
| `TG_ALLOWED_IDS` | пусто | id пользователей Telegram через запятую; если задано, остальным бот откажет |
| `TG_ALERT_POLL` | `60` | раз в сколько секунд проверять новые оповещения, `0` выключает |
| `TG_DATA_DIR` | `/var/lib/proxmox-tg-bot` | где хранятся привязанные аккаунты |

Если PegaProx стоит на другом сервере, укажите его адрес в `PEGAPROX_URL` и лучше включите
проверку сертификата (`PEGAPROX_VERIFY_TLS=/путь/к/ca.pem`).

## Подключение аккаунта

1. В PegaProx: «Мой профиль → API-токены» → создать токен. Роль токена можно выбрать
   ниже своей, например `viewer`, если из Telegram нужно только смотреть.
2. В личном чате с ботом: `/login pgx_...`. Бот проверит токен и сразу удалит сообщение.
3. `/menu` открывает кластеры.

`/logout` отвязывает аккаунт. Сам токен после этого лучше отозвать в PegaProx.
Если токен отозвать или у пользователя отнять права, бот сразу перестанет их иметь:
каждое действие проверяет сам PegaProx.

## Безопасность

- Токены хранятся зашифрованными (`accounts.json` + ключ `secret.key`, оба с правами 0600).
  Каталог данных должен быть доступен только пользователю бота.
- Токен принимается только в личном чате; в группе бот удалит сообщение и попросит
  отозвать токен.
- Кнопки привязаны к пользователю: чужие кнопки в группе ничего не делают.
- `TG_ALLOWED_IDS` закрывает бота от посторонних полностью.
